# Фрагменты кода Tiny Swords: Kingdoms

[← О проекте](../README.md)

Выдержки взяты из рабочего исходного проекта игры 25 ноября 2026 года. Указанные строки относятся к этой локальной версии. Полные исходные файлы не опубликованы; ниже оставлены их имена для происхождения примеров. Тела функций, имена переменных и отступы сохранены. Добавлены только комментарии о формате выдержек, а отдельные необходимые объявления скопированы из тех же файлов.

Это материал для чтения и обсуждения кода. Поля класса и окружающие системы могут отсутствовать, поэтому `.gd`-файлы не предназначены для самостоятельного запуска.

## Маска нажатия для текстурной кнопки

[Открыть код](ui_click_mask.gd) · источник: `scripts/ui_hit_area.gd`, строки 4, 7, 10–26.

**Задача.** Прозрачные углы декоративной кнопки не должны принимать нажатия. Маску по альфа-каналу имеет смысл переиспользовать у кнопок с одной текстурой.

Метод проверяет кнопку и изображение, ищет готовую `BitMap` в словаре и создаёт её при первом обращении. В ключ входят путь текстуры и порог прозрачности.

**Контекст и границы.** Здесь используются файловые текстуры с различимыми `resource_path`. Для динамических текстур с пустым путём этот ключ потребовал бы другого идентификатора. Порог в ключе округляется до трёх знаков. Это конкретный приём из игры, а не универсальная библиотека кэширования текстур.

## Измерение текста интерфейса

[Открыть код](text_measurement.gd) · источник: `scripts/ui_text_guard.gd`, строки 9, 273–299, 302–315.

**Задача.** Определить, помещается ли подпись в выделенный прямоугольник, в том числе после смены языка.

`_text_fits` учитывает режим переноса `Label` и `Button`. Для текста без автоматического переноса отдельно измеряются строки: используется максимальная ширина, а высота зависит от числа строк. Размер проверяется по двум осям с небольшим допуском.

**Контекст и границы.** Выдержка измеряет обычный текст; она не реализует весь процесс подбора шрифта, отступов и размещения элементов. Шрифт, размер и доступная область уже подготовлены вызывающим кодом. Это не обработчик разметки `RichTextLabel`.

## Ограничение повторяющихся звуков

[Открыть код](audio_cooldown.gd) · источник: `scripts/audio_manager.gd`, строки 855–865, 868–872.

**Задача.** Частые звуки в одном месте не должны накладываться без ограничения, но событие в другой части карты не должно теряться из-за общего таймера.

`_can_play` хранит время последнего разрешённого события по составному ключу. `_world_cooldown_key` группирует позиции в клетки через `floori`, в том числе для отрицательных координат.

**Контекст и границы.** `EVENT_COOLDOWN` — таблица интервалов, `_last_played_at` — словарь времён, `WORLD_COOLDOWN_CELL_SIZE` — положительный размер клетки. Их настройки и жизненный цикл аудиосистемы в выдержку не входят. Измерение реального времени здесь относится к воспроизведению звуков.

### Регрессионная проверка звука

Непрерывный фрагмент тела `_test_audio_regressions` из `scripts/defect_regression_test.gd`, строки 751–760. Существующий тест проверяет два разных исхода: повтор в той же клетке блокируется, а первая попытка в соседней клетке разрешается.

```gdscript
	AudioManager._last_played_at.clear()
	assert(AudioManager._can_play("impact_melee_unit", "0:0"))
	assert(
		not AudioManager._can_play("impact_melee_unit", "0:0"),
		"The same world cell bypassed its event cooldown"
	)
	assert(
		AudioManager._can_play("impact_melee_unit", "1:0"),
		"A global event cooldown still suppresses a different world cell"
	)
```

Этот блок исполняется внутри тестового окружения игры с настроенным `AudioManager`; отдельно он не запускается. Полный набор регрессионных тестов здесь не распространяется. При подготовке портфолио проверено точное совпадение выдержки с исходником; полный тест игры в рамках этой публикации не запускался.

## Непересекающиеся множества

[Открыть код](disjoint_sets.gd) · источник: `scripts/battlefield.gd`, строки 4273–4282, 4285–4293.

**Задача.** Находить представителя компоненты и объединять две компоненты.

`_union_find_root` сначала находит корень, затем повторным проходом перенаправляет родителей на него. `_union_find_merge` объединяет только разные корни. Это общеизвестный алгоритм union–find, применённый в игровом коде; процесс построения карты в пример не входит.

**Контекст и границы.** Массив должен описывать корректный лес родителей с допустимыми индексами. Методы меняют его на месте. Сжатие путей реализовано, объединение по рангу или размеру в этой выдержке не используется; соответствующие гарантии сложности здесь не заявляются.
